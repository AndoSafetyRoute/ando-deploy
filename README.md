# 안도 (Ando) — 배포용 레포지토리

교통약자를 위한 접근성 경로 안내 앱. 이 레포는 `ando-FE`(개발용 프론트 레포)와 `ando-BE`(개발용
백엔드 레포)에서 실행에 필요한 소스만 골라 배포/전달용으로 정리한 스냅샷입니다.

## 구조

```
ando-deploy/
├── frontend/   Expo(React Native) 앱 — 자세한 설정은 frontend/README.md
└── backend/    FastAPI 서버(경사도 기반 경로탐색 엔진) — 자세한 설정은 backend/README.md
```

두 프로젝트는 독립적으로 실행되고, 프론트가 `EXPO_PUBLIC_ROUTE_API_URL`로 백엔드 주소를 바라보는
구조입니다. 로컬 개발 시에는 백엔드를 먼저 띄우고, 그 주소를 프론트 `.env`에 넣어주세요.

## 버전 브랜치

- `main` — 항상 최신 버전
- `release_v1`, `release_v2` … — 각 배포 시점의 스냅샷

새 버전을 배포할 때는 `main`에서 `release_vN` 브랜치를 새로 따는 방식을 씁니다.

## 시작하기

1. `backend/README.md`를 따라 백엔드부터 띄웁니다 (경사도 그래프 데이터가 커서 최초 준비에
   시간이 좀 걸립니다).
2. `frontend/README.md`를 따라 프론트를 띄우고, `.env`의 `EXPO_PUBLIC_ROUTE_API_URL`이 1번에서
   띄운 백엔드 주소를 가리키게 설정합니다.

## 이 레포에 포함되지 않은 것 (로컬에서 별도로 준비해야 함)

두 README에 각각 상세히 정리되어 있지만, 공통적으로 다음은 용량이 크거나(수백MB~1GB대) 민감정보라
git에 커밋하지 않았습니다:

- 프론트: `.env`, `google-services.json`
- 백엔드: `.env`, `firebase-key.json`, `data/` 아래 경사도 그래프 원본 데이터

## 이번 버전 (release_v4)

release_v3에 실사용 버그수정 2건 + 경로 로직 정리 + UI 수정을 더한 버전입니다.
release_v3는 그대로 남겨뒀으니, 이번 버전에 문제가 생기면 release_v3로 되돌릴 수 있습니다.

### 버그수정
- **도보 "안내 시작" → 홈으로 튕기던 문제**: `ROUTE_COMPARE_ENABLED=true`에서
  `frontend/app/route.tsx`의 네비게이션 어댑터에 `RouteCompare` 케이스가 없어
  `router.replace("/")`(홈 리셋 fallback)로 떨어지던 것 — 케이스 추가.
- **지방 지역 검색 시 에러 팝업**: 서울 전역 그래프 밖 좌표는 경사도가 그래프
  GeoJSON에 함께 구워져 있어 거리 우선 경로도 계산 불가. `CoverageError`
  (`out_of_service_area` 코드)로 구조화 응답 + 프론트는 스크리한 "경로 탐색
  실패" 팝업 대신 "현재 서울 지역만 제공" 안내 + 서울 bbox 밖이면 길찾기 시작
  비활성화(우아한 차단).

### 경로 탐색·안내 로직
- **도보 경로 비교 2종으로 축소**: `RouteCompareScreen`에서 "사용자 맞춤형"
  비활성 자리표시 카드 제거 → ① 거리 우선, ② 유형별 추천 2장만. 테스트
  데이터/⑨ 배치 학습이 들어와 BE가 personal 후보를 채우면 코드 변경 없이
  3번째 카드 자동 부활.
- **탐색시간 프로파일링 계측 추가**: `/route` 요청당 구간별 소요시간을 한 줄
  (`[PROFILE] …`)로 출력. `ROUTE_PROFILE=0`으로 끔. (개선안은 세션 로그 참고 —
  `/route` 이중 호출 제거, speed_profile 요청 1회 캐시, 결과 캐싱 등.)
- **횡단보도 표시 제거**: 판별 로직이 애초에 미구현 상태였음(BE가 `crossings`를
  응답한 적 없어 프론트에 항상 "횡단보도 0회"로 표시). `WalkContent`에서 관련
  타입·매핑·StatPill 제거.

### UI
- **책갈피 화면**: 지도를 현위치 기준으로 표시 + 현위치(GPS) 버튼 추가
  (HomeScreen과 동일 패턴). 하단 네비의 GPS 아이콘 버튼도 실제 현위치 이동으로 수정.
- **경로 검색 화면**: 카테고리 버튼(카페/음식점/휠체어충전소) 행을 제거하고
  즐겨찾기로 추가한 장소 버튼 행으로 통일(가로 스크롤, 스크롤바 숨김). 관련
  죽은 코드 정리.
- **경로 설정 화면**: 보행 경로 안내 문구를 "6가지 유형별 추천 경로를 경사도에
  따라 제공합니다"로 변경. 출발지에만 있던 GPS 버튼을 도착지에도 추가.

### 미포함 / 후속
- 4-1 대중교통 실시간 도착정보: 현재 카카오 대중교통 API가 주는 필드 조사만
  완료(버스 구간 소요시간은 `step.properties.time`으로 받으나 실시간 도착정보는
  아님, 정류장은 이름만 옴). 서울시 실시간 API 연동은 인증키 발급 + 실호출
  확인이 필요해 별도 진행.
- 이 스냅샷의 프론트/백엔드 수정은 다음 스냅샷 재생성 때 `ando-FE`/`ando-BE`
  개발 레포에도 반영 필요.

## 이전 버전 (release_v3)

release_v2(개인화 파일럿 단독)에 접근성 라우팅 확장 + 여러 실사용 버그수정을 더한 버전입니다.
release_v2는 그대로 남겨뒀으니, 이번 버전에 문제가 생기면 release_v2로 되돌릴 수 있습니다.

### 서울 전역 접근성 라우팅
- 백엔드 라우팅 그래프가 용산구 전용(5m)에서 **서울 전역(10m)** 으로 확장 가능해짐
  (`GEOJSON_PATH` 환경변수로 전환 — 이 레포의 `.env.example` 기본값은 서울 전역).
  그래프 20만 노드 초과 시 CCH 엔진 자동 활성화.
- 지하철역 접근성(엘리베이터/에스컬레이터/휠체어리프트, 고장 상태 실시간 제외) +
  휠체어 급속충전기 위치 + 저상버스 노선별 보유율 API 추가.
- 목적지를 지하철역 이름으로 지정하면 유형별 최적 출구로 자동 스냅(`end_station_name`).
- **버그수정**: 그래프 범위 밖 좌표가 검증 없이 "가장 가까운 아무 노드"로 스냅되면서
  대중교통 도보구간 소요시간이 "몇 시간"으로 부풀려지던 문제 — 스냅거리 검증(서버) +
  구현속도 하한선 검증(프론트) 이중 안전망 추가.

### 개인 맞춤 경로 — 데이터 수집
경사 비용 곡선 `c_u(g)` 개인화를 위한 **신호 A~D 수집 파이프라인**이 들어갔습니다.
아직 학습(⑨ θ 적합)은 없고, **데이터를 모으는 코드만** 완성된 상태입니다.
설계 근거 문서(`ando_ml_plan_v2` 등)는 개발 레포에 있습니다.

- **백엔드**: `POST /collect/batch`(신호 A~D 배치, `(uid,session_id,seq)` 멱등),
  `POST /route?candidates=compare`(경로 비교용 후보 배열), 신규 테이블 8종,
  `/collect/batch` 평지 관측으로 `v̄_flat` EMA 갱신 + 캘리브레이션 게이트(평지 누적 300m),
  개인화 basis(비균등 매듭)·개인 metric 캐시(⑤⑥⑧), `GET /user/personalization-status`
  (캘리브레이션 진행률). CCH가 도는 환경에서 end-to-end 확인됨.
- **프론트**: GPS 콜백에서 0.5% 경사 bin 전환 계측(⑪), 배치 전송 큐·오프라인·멱등(⑫),
  구간 평가(⑭)·왕복 방향교대(⑮) 화면 — 활성. **3경로 비교(⑬)는 이번 버전부터 켜짐**
  (`src/personalization/config.ts`의 `ROUTE_COMPARE_ENABLED=true` — "경로가 하나만
  뜬다"는 리포트에 대응해 파일럿 3세션 로그 전수검증 없이 먼저 켠 상태. 표시 순서 고정
  거리우선→유형별→맞춤형, 사용자 맞춤형 후보가 없으면 "준비중" 비활성 카드로 자리 유지).
  선택한 후보의 지도색·회전음성안내(`navigation_segments`/`waypoints`)를 후보 전부에
  대해 계산해 전달(이전엔 유형별 후보만 있어서 다른 후보 선택 시 누락됐음).
- **지도 경사 색상**: zone 판정에 완충(hysteresis)+디바운스 적용 — 라우팅 계산 자체는
  무영향, 지도에 표시되는 색만 안정화(실측: zone 전환 빈도 70.1% 감소).

### 그 외 버그수정
- 홈 화면 진입 시 위치가 서울역에 고정돼 보이던 문제, 카페/음식점 검색이 GPS 확보 전
  캐시에 박혀 계속 서울역 근처만 나오던 문제
- 뒤로가기를 여러 번 눌러야 홈으로 돌아가던 문제 — 홈 버튼 전부 `router.dismissTo("/")`
  통일 + 도보/대중교통/자동차 단일경로 안내 시작을 push 대신 replace로 변경
- 회원탈퇴(`DELETE /user/me`), 최근 검색기록(`GET/POST /user/search-history`) 추가
- PathFinder/ODsay 관련 코드·설정 제거(미사용 확정 — 대중교통 경로탐색은 프론트가
  카카오 API로 직접 조회)

미포함(별도 작업): ⑨ θ 배치 학습 스크립트, 9.2절 실측 #4(우회 초과 빈도 — 운영 로그 필요).

### 배포 담당자 확인 필요
- **`GEOJSON_PATH`가 실제로 서울 전역 파일을 가리키는지** — 위 접근성 라우팅 확장과
  3경로 비교(distance/personal 후보) 둘 다 이 값에 좌우됩니다. Yongsan 전용(5m) 그래프
  그대로면 CCH가 안 켜져서 "경로가 하나만 뜨는" 현상이 재발합니다.
- `ROUTE_COMPARE_ENABLED=true`는 파일럿 검증 전 임시 조치 — 실기기에서 2~3경로가
  정상적으로 뜨는지 확인 후 문제 있으면 `frontend/src/personalization/config.ts`에서
  다시 `false`로.
- `EXPO_PUBLIC_ROUTE_API_URL`은 빌드 타임에 번들에 박힙니다 — 앱 빌드 시 실제 배포
  서버 주소로 설정된 채 빌드됐는지 확인.
- `/collect/batch`는 로그인 필수라 파일럿 테스터 전원 로그인 여부 확인 필요.

## 알려진 제한사항

- **서울역 인근 도보 경로 우회 문제**: 서울역 인근에서 출발/도착하는 경로가 실제 거리보다 훨씬
  긴 우회 경로로 계산되는 현상이 있습니다 (예: 서울역↔서울숲 직선거리 약 5.9km인데 계산된 최단
  거리가 14km대). 서울역 서쪽의 대형 철도 조차장 주변 보행로 데이터에 연결 성분이 끊긴 지점이
  있고, 그래프 빌드 시 성분을 이어붙이는 반경(`BRIDGE_GAP_M`, 기본 50m)을 넘는 실제 빈틈이 있는
  것으로 추정됩니다. 이 경로 자체가 CCH 엔진의 "최단거리" 계산 결과라 코드 버그가 아니라 원본
  보행로 지오데이터의 빈틈으로 보이며, 근본 해결에는 `data/roads-seoul.geojson`의 서울역 인근
  보행로 데이터 보강 또는 `config.py`의 `BRIDGE_GAP_M` 조정이 필요합니다. 자세한 내용은
  `backend/README.md`의 "알려진 이슈" 절 참고.
